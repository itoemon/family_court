## エージェント一覧

| ニックネーム | 役割 | 実体 | 位置づけ |
|---|---|---|---|
| **リード** | 要件定義・方針決定・PM・**テスト実行・アドバサリアル検証・コードレビュー** | Claude Code（対話チャット） | 中核 |
| **アーキ** | 設計書作成 | Claude CLI エージェント（agents.sh） | 中核 |
| **ビルド** | コード実装 | Claude CLI エージェント（agents.sh）/ ハーネス Agent（fallback） | 中核 |
| **オーディ** | 品質監査・コードレビュー | Claude CLI エージェント（agents.sh） | **任意**（リード＋コパで代替可） |
| **テスタ** | E2E 実行 | Claude CLI エージェント（agents.sh） | **任意**（リードが直接 playwright を回す方が速く確実） |
| **コパ** | PR最終レビュー | GitHub Copilot | 中核（実バグ検出力が高い） |

**Why:** 打ちやすさ重視でカタカナ短縮形に統一。役割が直感的に伝わる命名。

**2026-07-05 リーン化（MON-001 セッションの実績を反映）:** テスタ/オーディの独立 CLI エージェントは、リードが直接テスト（playwright fast-path）＋アドバサリアル検証＋設計/コードレビューを行い、コパが PR 最終レビューする方が速く確実だった（コパは PR-A/PR-B とも実バグを検出）。よって**テスタ・オーディは任意扱い**とし、標準フローは「リード（要件・設計レビュー・テスト・アドバサリアル・PR・memory）→ アーキ（設計）→ ビルド（実装）→ リードがテスト＋レビュー → コパ（PR レビュー）」。テスタ/オーディ agent は大規模変更で追加のカバレッジが欲しいときに任意起動。

**How to apply:** 会話中でエージェントを指すときはこのニックネームを使う。ドキュメントやシェルスクリプトにも同じ名称を使用する。
