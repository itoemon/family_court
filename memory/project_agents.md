## エージェント一覧

| ニックネーム | 役割 | 実体 | 位置づけ |
|---|---|---|---|
| **リード** | 要件定義・方針決定・PM・設計/コードレビュー・最終アドバサリアル検証・PR 判断・編成 | Claude Code（対話チャット・harness） | 中核 |
| **アーキ** | 設計書作成 | **harness サブエージェント（Agent ツール・general-purpose）** | 中核 |
| **ビルド** | コード実装 | **harness サブエージェント（Agent ツール・general-purpose）** | 中核 |
| **オーディ** | **独立セキュリティ監査**・品質監査 | **harness サブエージェント（Agent ツール・general-purpose）** | **中核**（security/お金絡みは必須） |
| **テスタ** | E2E 実行 | リード直の playwright fast-path | **任意**（リードが直接回す方が速く確実。agent 化しない） |
| **コパ** | PR最終レビュー | GitHub Copilot | 中核（実バグ検出力が高い） |

**★2026-07-16 実行基盤の再設計:** アーキ/ビルド/オーディの実体を **`scripts/agents.sh`（nested `claude -p`）から harness の `Agent` ツール（独立サブエージェント）へ全面移行**。agents.sh は無出力死・観測性ゼロ・孤児化で信頼できず **deprecated**。harness サブエージェントは信頼性・観測性（構造化結果が返る）・独立性すべてで上回る。リードが Agent ツールで各役割を独立起動して編成する。詳細は [[feedback-pipeline-runner]]。

**Why:** 打ちやすさ重視でカタカナ短縮形に統一。役割が直感的に伝わる命名。

**思想（ダイチ）: リードはプロマネに徹し、独立した専門家に見させることで質を上げる。** 実装した人・指揮した人とは別の独立した目（特にセキュリティ）に固有の価値がある。

**2026-07-05 の整理（MON-001 セッションを経て）:**
- **オーディは中核として維持**。auth / 決済 / RLS / 暗号 が絡む変更では**必須**（独立セキュリティ監査の層は決済アプリで価値大。リード自身のレビューは"自分の近くの仕事"で盲点が出るため、独立の目を残す）。軽微な docs/リファクタでのみ任意。これで**独立したセキュリティの目が 3 層**（オーディ＋リードのアドバサリアル＋コパ）。
- **テスタのみ任意**（リード直の playwright fast-path が速く確実。UI ターン制御でテスタ agent は詰まりがち）。大規模変更で追加カバレッジが欲しいときに起動。
- リードは PM 寄り（要件・設計レビュー・方針・最終判断）に軸足を戻す。全部を自分でやるのでなく、独立専門家（アーキ/オーディ/コパ）に見させて統括する。

**権限のかけ方（ソフト制御・ダイチ確認）:** agents.sh は `--dangerously-skip-permissions` で動くため `--allowedTools` のハード制限は効かない。各エージェントの**プロンプト（`docs/agents/*.md`）のディレクトリ権限記述で範囲を制約**する（例: オーディは「書き込み可能=監査ログのみ、実装コードは読み取り専用」）＋リードの管理で担保。ローカル信頼リポジトリ前提。

**How to apply:** 会話中でエージェントを指すときはこのニックネームを使う。ドキュメントやシェルスクリプトにも同じ名称を使用する。
